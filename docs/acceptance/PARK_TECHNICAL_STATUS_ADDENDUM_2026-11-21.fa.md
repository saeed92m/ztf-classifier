## ۶. اقدام‌های بعدی به ترتیب

### اقدام ۱ — اجرای محلی نسخهٔ آزمایشگاهی

از Runbook موجود در مخزن استفاده کن. یک Checkout جدا بساز. Python 3.11 را به‌کار ببر. پوشه‌های کاری فعلی را Reset یا Clean نکن.

در دستگاه ارائه:

1. آزمون زندهٔ دو OID را اجرا کن.
2. API و Workbench را اجرا کن.
3. دو OID را جداگانه بارگذاری کن.
4. نمایش فیلترهای g و r، تعداد Epoch، جدول خام، QC و Provenance را بررسی کن.
5. JSON را Export کن.
6. تصویر صفحه، خروجی آزمون، نسخهٔ محیط، SHA-256 فایل و زمان UTC را نگه دار.

تا پایان این آزمون، نسخهٔ آزمایشگاهی آمادهٔ ارائه نیست.

### اقدام ۲ — نگه‌داشتن دروازهٔ مدل بسته

آرتیفکت اصلی `baseline_v0.2` در ممیزی‌های محلی و شواهد موجود احراز نشده است. تا بازیابی و تطبیق manifest، hash مورداعتماد، schema، ترتیب ویژگی‌ها، ترتیب کلاس‌ها و provenance، inference تولیدی **BLOCKED** می‌ماند. artifact آزمایشگاهی جایگزین نیست. این پیوست مجوز اجرای ممیزی جدید یا ارسال داده را صادر نمی‌کند.

### اقدام ۳ — توسعهٔ مسیر اصلی محصول

پس از تثبیت دو PR فعلی، اولویت فنی بعدی:

1. افزودن انتخاب صریح منبع DR24 به مسیر عادی ObservationService؛
2. نگه‌داشتن ALeRCE به‌عنوان منبع مستقل؛
3. جلوگیری از جایگزینی خاموش منابع؛
4. ثبت هویت و ارتباط OIDها با شواهد AOIC؛
5. حفظ دادهٔ خام و تعریف قراردادهای مستقل زمان، فوتومتری و QC؛
6. فقط پس از اعتبارسنجی، اتصال Feature Mapping و مدل نسخه‌بندی‌شده.

### اقدام ۴ — تکمیل Park MVP و محصول اصلی

Park MVP باید روی یک Cohort کامل و از پیش تعریف‌شده اجرا شود. نمونهٔ دو OID معیار پذیرش محصول نیست.

مسیر بلندمدت شامل مدیریت داده، QC، مهندسی ویژگی، مدل، عدم‌قطعیت، OOD، تحلیل ناهنجاری، اولویت‌بندی اجرام، داشبورد، API، گزارش تکرارپذیر، نصب چندسکویی و سازوکار بازبینی انسانی است.

شبکهٔ مشارکت انسانی (CIN) یک توسعهٔ مستقل و آینده‌نگر است. آن را وارد مسیر بحرانی نسخهٔ پارک نمی‌کنیم.
