## ۴. محدودیت‌های نمونه

1. هر ۳۰ OID از یک partition، یک field و فیلتر باند g هستند. این نمونه نماینده کل آسمان نیست.
2. OID شناسه رکورد پیمایش است؛ ۳۰ OID معادل ۳۰ جرم اخترفیزیکی مستقل و تأییدشده نیستند.
3. کنترل r شامل OID مستقل `264214400000912` با ۱۲۳ epoch است. هیچ تطبیق فیزیکی یا ادغامی با رکوردهای g انجام نشده است.
4. کاتالوگ داخل بسته فقط ۳۰ OID دارد. فایل کامل ۱۵۰ ردیفی Objects Table در داده‌های آرشیوشده موجود نیست؛ فقط هش snapshot و اطلاعات نمونه‌گیری ثبت شده است. هش ثبت‌شده snapshot: `4cc5827cd077252ceca99af587e4091e5cb5b4e7ca00a45d0d3a07bbfaaa52c7`. بازیابی فایل اصلی و تطبیق هش، تعداد ردیف و schema همچنان لازم است.
5. QC موجود توصیفی است و سیاست تولیدی انتخاب epoch نیست.
6. HMJD، mag، magerr، clrcoeff و catflags به شکل منبع حفظ شده‌اند. تبدیل زمان، اصلاح رنگ و انتخاب epoch انجام نشده است.

## ۵. اجرای آفلاین

فایل `index.html` مستقیماً از فایل‌سیستم محلی با Chrome یا Edge باز می‌شود. بررسی ایستا نشان داد فایل HTML شامل منابع لازم است و ارجاع خارجی به اسکریپت یا stylesheet، فراخوانی `fetch` یا import خارجی ندارد. بنابراین برای اجرای بسته، Python، دستور `python -m http.server 8000`، وب‌سرور محلی، اینترنت یا API Key لازم نیست.

**تست دستی روی لپ‌تاپ واقعی ارائه هنوز باید انجام شود.** بررسی ایستای HTML جایگزین تست مرورگر روی دستگاه ارائه نیست.

## ۷. موارد بعدی

1. اجرای دستی ZIP اصلاح‌شده روی لپ‌تاپ ارائه و ثبت نتیجه.
2. بازیابی فایل اصلی ۱۵۰ ردیفی Objects Table و بررسی hash/schema.
3. تکمیل مسیر DR24 در Application Service با انتخاب صریح منبع و بدون fallback پنهان به ALeRCE.
4. تأیید قراردادهای versioned برای هویت OID، cross-match، HMJD، فوتومتری و QC.
5. اجرای کامل workflow برای ۵ تا ۱۰ جرم فیزیکی تأییدشده.
6. پس از موفقیت گام قبل، اجرای نمایش هدایت‌شده ۳۰ تا ۵۰ منبع.
7. اجرای ارزیابی علمی مستقل با split در سطح جرم و زمان.

## ۸. حفاظت از baseline و دامنه
